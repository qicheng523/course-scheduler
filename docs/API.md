> **这份文件是 A、B、C 三个人共同的约定。** 谁都不许自己偷偷改字段名。

## 0 两条总规矩

1. **数据库里时间存"分钟数"**（8:00 = 480），**接口上时间用 `"HH:mm"` 字符串**（`"08:00"`）。转换只在 C 的后台做。
2. 所有接口返回 **JSON**；出错返回 `{"detail": "中文说明"}`，`detail` 要能直接给用户看。

## 0.5 特殊时段：晚自习（v0.2 新增，全项目最重要的一条）

**晚自习仍然是"可以学习的时间"，但它不是普通空闲时间。**

- 周一到周五 **19:00–21:00** 是晚自习（**120 分钟**）。
- 去晚自习、从晚自习回来都要走路，**前后各留 10 分钟**：`18:50–19:00` 和 `21:00–21:10` **不排任务**。
- **任务块不许横跨晚自习的边界**：一个任务要么整段在 `19:00–21:00` 里面，要么整段在外面。

| 能不能排 | 例子 |
|---|---|
| ✅ 可以 | 17:50–18:50（晚饭前的整段） |
| ✅ 可以 | 19:00–20:30（整段在晚自习里） |
| ✅ 可以 | 19:30–20:45（整段在晚自习里） |
| ✅ 可以 | 21:10–21:30（回宿舍之后的 20 分钟） |
| ❌ 不行 | 18:30–19:30（跨了 19:00，人还在路上） |
| ❌ 不行 | 20:00–21:20（跨了 21:00，人已经要走） |
| ❌ 不行 | 18:40–19:20（跨了 18:50 这条通勤线） |

- **周六、周日没有晚自习**，整天连续可用（07:30–21:30）。

**算法上怎么实现（一句话）**：算完空闲段以后，把每一段在 **18:50 / 19:00 / 21:00 / 21:10** 这四个时刻切开；切开后不足 15 分钟的碎片（正好是那两段 10 分钟通勤）自动丢掉。

**切开之后长什么样**（周一、周二、周四、周五，第 8 节 17:50 下课）：

| 原来 | 现在 |
|---|---|
| 傍晚一整段 17:50–21:30（220 分钟） | **17:50–18:50（60 分钟）** + **19:00–21:00（120 分钟，晚自习）** + **21:10–21:30（20 分钟）** |

周三下午没课时：`15:40–18:50`（190 分钟）+ `19:00–21:00`（120 分钟）+ `21:10–21:30`（20 分钟）。

> **单个任务最长的上限因此变成 120 分钟**（晚自习那一段）。超过 120 分钟的，只能放周末，或者周三下午那段。排不下要进"未排"并写清原因。

**为什么这么定**：任务要是横跨晚自习边界，等于要求人"在路上就开始写作业"或者"把自习室的时间劈成两半"，现实里做不到，答辩时老师一问就露馅。

## 3 接口长什么样（A 照这个做页面，B 照这个验数据）

### ① 查课程

```http
GET /api/courses?term=2026f
```

```json
{
  "items": [
    {"id": 1, "name": "中国近现代史纲要", "weekday": 1, "start": "08:00", "end": "09:40", "location": "28-A303"},
    {"id": 2, "name": "高等数学AI",       "weekday": 1, "start": "14:00", "end": "15:40", "location": "1-0206"}
  ],
  "total": 19
}
```

### ② 新增课程

```http
POST /api/courses
Content-Type: application/json

{"name": "高等数学AI", "weekday": 1, "start": "14:00", "end": "15:40", "location": "1-0206"}
```

成功：`201` + 返回这条记录（带 `id`）。

### ③ 修改 / ④ 删除

- `PUT /api/courses/{id}`：body 同新增，成功 `200`
- `DELETE /api/courses/{id}`：成功 `204`（没有内容）

### 错误码（A 要按这个显示中文）

| 情况 | 状态码 | 返回 |
|---|---|---|
| 星期不是 1–5 | 422 | `{"detail": "星期只能是 1 到 5（周六周日没有课）"}` |
| 时间格式不对 | 422 | `{"detail": "时间要写成 08:00 这样的格式"}` |
| 结束早于开始 | 422 | `{"detail": "结束时间必须晚于开始时间"}` |
| 和已有课程时间重叠 | 409 | `{"detail": "这门课和「高等数学AI」时间冲突"}` |
| 改/删的 id 不存在 | 404 | `{"detail": "课程不存在"}` |

> **409 是重点**：A 的页面要把这句话原样显示在表单下面，不要只显示"出错了"。

### ⑤ 查空闲段（v0.4 新增，D3 用；C 实现，A 后面做计划页要用）

```http
GET /api/slots?date=2026-11-19
```

```json
{
  "date": "2026-11-19",
  "weekday": 4,
  "items": [
    {"start": "09:40", "end": "10:10", "minutes": 30,  "kind": "free"},
    {"start": "19:00", "end": "21:00", "minutes": 120, "kind": "evening"}
  ],
  "total": 2
}
```

**返回格式（冻结，谁都不许改字段名）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | 文本 | 原样返回请求的日期 |
| `weekday` | 整数 1–7 | 那天是星期几（1=周一） |
| `items` | 数组 | 当天空闲段，**按时间升序**，每段至少 15 分钟 |
| `items[].start` / `items[].end` | 文本 `"HH:mm"` | 段的起止 |
| `items[].minutes` | 整数 | `end - start`，方便前端直接显示"60 分钟" |
| `items[].kind` | 文本 | `free` = 普通空闲；`evening` = 晚自习 19:00–21:00 那一段（可以排任务，且优先） |
| `total` | 整数 | 段数，等于 `items` 的长度 |

**五条保证（算法必须做到，测试要测）**

1. 只出现在 **07:30–21:30** 之内，绝不越界。
2. **不和当天的课、固定事件重叠**。
3. **不出现** `18:50–19:00`、`21:00–21:10`（通勤），也**没有一段跨过 19:00 或 21:00**。
4. **周一到周五** 19:00–21:00 必须是**独立的一段**，`kind` 为 `evening`，不许和前后拼起来。
5. **周六、周日** 不在 18:50/19:00/21:00/21:10 切开（周末没有晚自习）。

**错误码**

| 情况 | 状态码 | 返回 |
|---|---|---|
| `date` 不是 `2026-11-19` 这种格式 | 422 | `{"detail": "日期要写成 2026-11-19 这样的格式"}` |
| 那天一段空闲都没有 | **200** | `{"items": [], "total": 0, ...}`（不是 404） |

> **`kind` 只有 `free` 和 `evening` 两个值**，不要自己加 `late`、`nap`、`study`。后面排程靠这个字段判断"要不要优先放晚自习"。

### ⑥ 生成周计划（v0.5 新增，D5/D6 用；C 实现，A 做计划页要用）

```http
POST /api/plan/generate
Content-Type: application/json

{"week_start": "2026-11-16"}
```

`week_start` = 那一周的**周一**（工作日）。成功 `201`：

```json
{
  "plan_id": 1,
  "week_start": "2026-11-16",
  "blocks": [
    {"id": 11, "date": "2026-11-16", "start": "08:00", "end": "09:40", "kind": "course", "task_id": null, "title": "中国近现代史纲要"},
    {"id": 12, "date": "2026-11-16", "start": "19:00", "end": "20:30", "kind": "task",   "task_id": 1,   "title": "线性代数第二章习题"}
  ],
  "unscheduled": [
    {"task_id": 5, "title": "CS50 第 3 讲", "reason": "这一周的空档最长只有 30 分钟，任务需要 45 分钟"}
  ],
  "stats": {"scheduled": 1, "unscheduled": 1}
}
```

**返回格式（冻结）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `plan_id` | 整数 | 这次生成的计划 id（`plan` 表的主键） |
| `week_start` | 文本 | 原样返回 |
| `blocks` | 数组 | 这一周的**所有占用块**：课、固定事件、已排任务，**按 `date`、`start` 升序** |
| `blocks[].kind` | 文本 | 只有 `course` / `fixed` / `task` 三种（**不返回 `free`**，空闲段用 `/api/slots` 查） |
| `blocks[].task_id` | 整数或 null | 只有 `kind="task"` 时有值 |
| `blocks[].title` | 文本 | 课名 / 事件名 / 任务标题，页面直接显示 |
| `unscheduled` | 数组 | 没排进去的任务，**每条必须有 `reason`**（中文、能直接给人看） |
| `stats` | 对象 | `scheduled` / `unscheduled` 两个计数 |

**七条保证（算法必须做到，测试要测）**

1. **零重叠**：任何两个块不重叠；任务块不和课、固定事件重叠。
2. 每个任务块 **15 ≤ 时长 ≤ 120 分钟**（晚自习整段 120 是上限的由来）。
3. 任务块**不跨 19:00 / 21:00**，也不出现在 `18:50–19:00`、`21:00–21:10`。
4. 全部落在 **`week_start` 到 `week_start+6` 这七天之内**，且每天都在 **07:30–21:30** 之内；任务块还必须**不晚于该任务的 `deadline`**（截止已经过去还没排的，直接进 `unscheduled`，`reason` 写"截止时间已过"）。
5. **排序确定**：候选顺序 = 晚自习 > 周末整天 > 工作日白天空档，同档取最早；起点对齐 15 分钟网格（450 + 15k）。同样的输入跑两次，**结果必须一样**（不许用随机）。
6. 同一个 `week_start` **再生成一次会覆盖旧计划**（不会出现两套块叠在一起）。
7. 排不下的进 `unscheduled` 并写清原因，**不许悄悄丢掉任务**。

### ⑦ 查周计划（D6，A 的页面读这个）

```http
GET /api/plan/2026-11-16
```

- 成功 `200`，返回格式**和 ⑥ 完全一样**（`plan_id / week_start / blocks / unscheduled / stats`）。
- 这一周还没生成过 → `404` + `{"detail": "这一周还没有计划"}`。
- A 的计划页只调这一个接口就能把整周画出来；要"重新生成"就调 ⑥ 再调 ⑦。

> **`blocks` 里不放 `free`** 是故意的：页面画"课 + 事件 + 任务"三种实块，空档另用 `/api/slots` 画浅色背景，两者不会打架。
