# 技术栈与目录说明

> 用途：答辩讲 5 分钟时的"我们用了什么、怎么分工"素材；也用于你随时查"这个文件归谁管"。

## 1 技术栈：每一样只记一句话

| 技术 | 一句话解释 | 本项目里负责什么 |
|---|---|---|
| Python 3.12 | 编程语言 | 全部代码的运行环境 |
| FastAPI | 用 Python 写 Web 接口的框架，自动生成接口文档 | 提供 `/health`、课程、排程等接口 |
| SQLModel | 一个类 = 一张表 = 一份接口数据格式 | 定义课程、任务、计划、打卡表 |
| SQLite | 一个文件就是整个数据库，不用装数据库软件 | 数据存在 `data/app.db` |
| Jinja2 | 在 HTML 里插变量的模板引擎 | 把排程结果渲染成网页 |
| HTMX | 在 HTML 属性里写 `hx-get` 就能局部刷新，不用写 JS | 点按钮/提交表单无刷新更新 |
| Pico.css | 只写语义化 HTML 就自动好看的 CSS 库 | 全站排版，零手写设计 |
| pytest | 自动化测试框架 | 守住"排程结果不能错"这条底线 |

**为什么这个组合适合两周：** 全是"写一次、三处受益"的工具——SQLModel 一个类同时管建表和接口格式，HTMX 省掉前端框架，Pico.css 省掉设计，pytest 省掉手动回归。三人不用各自学一套。

## 2 目录职责（谁改哪个文件）

```
课表排程工作区/
├── app/                 后端应用（Python）
│   ├── __init__.py      包标记 + 版本号
│   ├── main.py          【入口】创建 FastAPI、挂模板/静态文件、注册路由
│   ├── db.py            数据库连接：引擎、会话、建表
│   ├── models.py        数据表定义（现在只有共用基类）
│   ├── routers/         【接口层】每个模块一个文件，只管"收请求、回响应"
│   ├── services/        【计算层】排程算法，纯函数，好测
│   ├── templates/       Jinja2 模板（HTML）
│   └── static/          静态资源（CSS / JS，已本地化，不依赖 CDN）
├── tests/               pytest 测试，文件名必须 test_*.py
├── scripts/             一次性脚本（环境自检等）
├── docs/                文档
├── data/                SQLite 数据库文件（自动生成）
├── requirements.txt     依赖清单（版本锁死）
├── pytest.ini           测试目录配置
└── README.md            安装 / 启动 / 测试说明
```

**分层规矩（很重要，答辩时能说清楚就是加分）：**

1. `routers/` 只做三件事：接参数、调 `services/`、返回结果。不写算法。
2. `services/` 里的函数**只吃普通参数、只吐普通数据**，不 import FastAPI。
3. `models.py` 只描述数据长什么样，不写业务流程。

这样划分的实际好处：排程算法可以坐在 `tests/` 里单独跑几百次，不用启动网页；哪天接口从 HTML 改成 JSON，`services/` 一行都不用动。

## 3 当前状态（骨架版 v0.1.0）

已经有的：

- `GET /health` → `{"ok": true}`，给测试和部署探针用
- `GET /` → 首页自检页，一眼确认 FastAPI / Jinja2 / Pico.css / HTMX 四件套通电
- SQLite 引擎与建表函数（`create_db_and_tables`）
- 会话依赖 `get_session`，明天写课程接口直接 `Depends(get_session)`

**还没有的**（按计划逐步加）：课程表、任务表、空闲段计算、排程算法、打卡、导出。

## 4 三个人怎么改代码不打架

| 文件/目录 | 谁负责 | 规则 |
|---|---|---|
| `app/services/`、`app/models.py` | 后端 | 改数据结构必须先说一声，会牵动所有人 |
| `app/templates/`、`app/static/` | 前端 | 只改 HTML/CSS，不动 Python |
| `README.md`、`docs/` | 文档 | 每次能跑通一个新功能就补两行 |

**冲突最少的做法：** 一人一个分支、一天合并一次；合并前先 `pytest -q` 跑绿。
